# Spec — デザイナートラック（デザイン実務9カテゴリ・33本）マスター構成書

> 目的：手法を検索して来るデザイナーを、実務記事から**ブランディングへ登らせる**新トラックを立ち上げる。
> 位置づけ：既存の経営者向けキーワード記事（SPEC_KEYWORD_ARTICLES.md）と対をなす第2トラック。この文書＋カテゴリ別md（01〜09）だけで執筆・実装に着手できる発注書。
> 作成日：2026-07-07 ／ 第1期＝9カテゴリ33本（num 301〜333）

---

## 1. 戦略 — なぜデザイナー向けか

Brandriの既存読者は経営者（target_reader: executive、75本）。本トラックの狙いは「**ブランディングというところに辿り着くデザイナーを増やす**」こと。

登らせる階段は全記事共通で4段：

```
手法（作り方・型）→ 原理（良し悪しを分ける観点）→ ブランド（コアから逆算する）→ 経営（なぜそれが利益に効くか）
```

- 入口は検索語（「バナー サイズ」「名刺 デザイン 作り方」「ロゴ 黄金比」）。**実務記事として単体で満足できる品質**を担保した上で、第03章で必ずブランディングに接続する。
- 経営者トラックが「痛み→ブランディングという名」で登るのに対し、デザイナートラックは「手法→ブランドコア→経営」で登る。**両トラックは記事同士の相互リンクで交差**させる（§6）。

## 2. 読者定義と語彙ルール（経営者トラックとの差分）

- **target_reader: ["designer"]** を新設。両読者に効く記事は ["designer","executive"] の併記可。
- 読者像：制作会社・インハウス・フリーランスの実務デザイナー。「上手く作れるが、提案が通らない／単価が上がらない／AIに置き換えられる不安がある」層。
- **経営者トラックの禁止語（トンマナ／クリエイティブ／デザイン思考等）は本トラックでは解除。** デザイナーの実語彙で書く。ただし乱用せず、glossaryの該当用語ページへリンクして定義を引き受けさせる。
- 共通で厳守：英字全大文字禁止（頭字語AI・VI・CI・UI・UX・SNS・LPは例外）／事実・数値・引用の創作禁止（sources明記）／煽らない。
- トーン：先輩デザイナーが隣で話す距離感。「べき」より「分かれ目」の提示。経営視点は説教にせず「単価と裁量が上がる話」として扱う。

## 4. 共通記事ハーネス（全33本同一）

分量：2,000〜2,600字（リード＋本文）。強調は `<em>…</em>`。既存スキーマをそのまま使う：num / cat / title / date / color / pattern / target_reader / slug / keyword / lead / sections / pullquote / takeaways / aside / related / sources。

| 章 | 役割 | 目安 |
|---|---|---|
| `title` | 検索語を含む実務見出し。ただし「〜まとめ」「〜選」型は禁止。問い・言い切りの形 | 1行 |
| `lead` | 制作現場のあるあるから始める。ブランド語はまだ出さない | 80〜120字 |
| `sections[0]`＝**01 制作の型** | すぐ使える手順・チェック観点。検索意図にここで答え切る | 450〜550字 |
| `sections[1]`＝**02 良し悪しの分かれ目** | 原理・比較の観点。黄金比等の技法は「目的でなく検証手段」として扱う | 450〜550字 |
| `sections[2]`＝**03 ブランドから逆算する** | このアウトプットはブランドの何を運ぶのか。コア（MVV・らしさ・選ばれる理由）が無いと02の判断基準が立たないことを示す。**全記事必須** | 450〜550字 |
| `sections[3]`＝**04 AIとの分業／経営にどう効くか** | AIに任せる工程と人が握る判断。この仕事が単価・指名・経営にどう返るか＋内部導線 | 400〜500字 |
| `pullquote` | 02の後。手法とブランドを繋ぐ一文 | 1文 |
| `takeaways` | 明日の制作で変えること 2〜4項目 | 各40字前後 |
| `aside` | 編集部の本音（既存記事と同トーン） | 1〜2文 |

**related（各記事3本必須）**の配合ルール：
1. 同カテゴリまたは隣接カテゴリのデザイナー記事 1本
2. **経営者トラックの既存記事 1本**（トラック交差。カテゴリ別mdで指定）
3. glossary用語ページ or entries or 診断（index.html#diagnostic） 1本

## 5. データ登録と実装

- 追加先：`project/data/articles.json` items。build-data.mjsのrenderArticlePage・sitemap登録は既存のまま流用可。
- color/pattern：既存パレット（#1E2340 #3D5070 #9B8CC8 #7BBAD4 #C8A4C4 #8CC4D0 × diagonal/dots/lines/grid）からローテーション。
- date：週3〜4本ペースで刻む。同一カテゴリを連投せず横断で混ぜる（§7）。
- keyword：カテゴリ別mdの指定語をそのまま使う（SEO主軸語）。

### 実装タスク（記事制作と並行）
1. **knowledge.htmlに「読者」フィルタ行を追加**：既存の種別／カテゴリ／用語チップ行に倣い、target_reader（経営者／デザイナー）のチップ行を追加。カテゴリチップが9個増えるため、読者で先に絞れる構造にする。
2. **ハブページ `for-designers.html` を新設**：ai-core-value.html（AI時代ハブ）と同型の特集ページ。「デザインから、ブランドへ。」をタイトル案とし、9カテゴリのマップ＋各カテゴリ基幹記事＋階段（手法→原理→ブランド→経営）の図解を置く。
3. **navに「デザイン」を追加**：index.htmlのnav-top（探す／ジャーナル／用語集／AI時代／事例／診断）に `for-designers.html` へのリンクを追加。
4. **sitemap.xml**：build-data.mjs経由で自動。ハブページのみ手動追加。
